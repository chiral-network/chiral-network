## Why

The book's adopted target design (Part I "Direction, precedence, and status" and "Desktop product: a local client that can share") makes the desktop a **local LLM workbench first and a marketplace client second**: find a model on Hugging Face, download it, load it on the user's own hardware and chat with it, with no wallet, chain, profile or network required. The book splits that design into five milestones, each needing its own OpenSpec change, tests and release gates before it is presented as implemented. This change specifies milestone (1): model download, the model library, pinned runtime management and local chat.

No specification covers any of it today. The desktop is a consumer client whose only inference path is a funded provider account; prompts are not persisted; the only engine lifecycle code (`engine_runtime.rs`) serves provider deployments configured by operator scripts. Without a specification, a desktop downloader could easily drift from the artifact contract that `scripts/provision-model.py` defines, follow arbitrary redirects, leak a Hugging Face token into the webview, load unverified bytes, or send local conversations off the machine. Book release gate 7 requires verified model download and installation to be qualified before the target design is presented as available.

## What Changes

- Search Hugging Face for GGUF repositories natively, show repository details as untrusted plain text, and select complete GGUF sets with sizes, declared quantization, license and a labeled fit estimate against natively detected memory; choose the install-time task, per-slot context, maximum output and chat template that the artifact contract fixes.
- Pin every download to a full commit, require an explicit per-download license acknowledgement, support gated repositories through an optional protected Hugging Face token file that must hold an `hf_` token and may not be another configured secret, and transfer files natively over HTTPS with per-hop DNS validation and address pinning, hop-by-hop allowlisted redirects (at most 5), no environment proxies, bounded JSON responses, pause/resume/cancel and disk-space checks.
- Verify every file's size and LFS SHA-256 and the GGUF structure before installation; partial or unverified files never become models.
- Install through a native Rust implementation of the provisioner's artifact contract, writing the same `chiral-artifact-sha256.json` and `chiral-model.json` bytes, so a desktop-downloaded model is usable unchanged by the CLI, the daemon and qualification.
- Add a **My models** library (repository, commit, quantization, size, capabilities, license, verification state; load, re-verify, reveal by installation identity, delete) with deletion refused while a model is in use and verification failures naming any unexpected file.
- Install the pinned llama.cpp runtime (v0.9.0, build b12110) only from the compiled official package allowlist, from the bundled archive at first launch or by an explicit download request, verified by archive hash and by its `chiral-runtime.json` inventory before every launch; show backends according to the platform status table and never as qualified; allow explicit runtime removal, refused while a loaded engine uses the runtime.
- Load and eject models in private loopback managed engine children with explicit settings (GPU offload, concurrency, devices, headroom; the per-slot context is fixed by the installation), disclose before every load that downloaded GGUF files are untrusted and the engine is not a sandbox, refuse settings that fail the fit check, recheck fit after loading, never restart or replay automatically, and stop every engine on every application exit the native runtime observes (including Cmd+Q and operating-system logout or shutdown).
- Add a **Chat** page: threads with per-thread system prompt, temperature, top-p and max tokens; native streaming over a proxy-free, redirect-free loopback engine client with stop/cancel, engine-reported token counts and a context-overflow pre-check before generation; untrusted plain-text output; funded network accounts in the same view under every existing consumer rule, scoped to the loaded network and wallet; explicit confirmation before a thread's content is sent to a provider.
- Store chat history only natively in protected app data, on by default (book *Author decisions* item 3) with a first-run disclosure that it is stored locally and can be turned off and cleared, a user preference to turn it off and controls to clear it.
- Make local mode work without a profile, wallet, chain or connectivity; add the Chat, Discover and My models navigation with the Network group in both navigation layouts, a status bar for engine, memory and downloads, and Settings sections for storage locations, the Hugging Face token file, runtimes and the chat-history preference, all behind the existing native boundary, with local state in the per-user non-roaming app data directory.

## Capabilities

### New Capabilities

- `desktop-model-acquisition`: Hugging Face search and repository details, GGUF set selection, fit estimates, commit pinning, license acknowledgement, gated-repository token handling, constrained resumable transfer, pre-installation verification, task/template/limit derivation, artifact-contract parity with `scripts/provision-model.py`, explicit-only downloads, and the My models library with verification and deletion rules.
- `desktop-local-runtime`: pinned runtime installation, removal and per-launch verification, backend availability by platform status, explicit load settings within installed limits, pre- and post-load fit checks, private loopback engine children, and eject/failure/quit behavior.
- `desktop-local-chat`: chat threads and parameters, native local streaming and cancellation, untrusted plain-text output, network threads under the existing consumer rules, explicit consent before thread content leaves the machine, protected local history controls, and session/window-lifecycle behavior for chat streams.
- `desktop-local-workbench`: local mode independent of any network profile or connectivity, the local-first navigation, the status bar, the new Settings sections, and the native boundary (permissions, protected storage, browser preview, diagnostics) for all local features.

### Modified Capabilities

None. The window lifecycle (`desktop-window-lifecycle`) is unchanged: closing still minimizes and keeps the native runtime running, and confirmed Quit still logs out before destroying the window. This change states what the new local state (engines, downloads, history) does under those existing rules inside its own capabilities, so it neither restates nor conflicts with the Quit requirement that `specify-desktop-share-online` is expected to extend. No consumer, funding, accounting or wire contract changes; network threads reuse existing native consumer operations.

## Impact

- Native (expected modules, names indicative): a Hugging Face client and download manager, a Rust artifact-contract module (GGUF reader, shard/task/template rules, canonical manifest and ModelSpec writer), a model library store, a runtime installer, a local engine manager built on `src-tauri/src/engine_runtime.rs`, a chat-history store, and new native commands wired in `src-tauri/src/desktop.rs`. Reuses `protocol.rs::canonical_json`, `wallet::open_secret_file`/`provider_config::read_secret`, and the `offer_registry.rs::public_ip` predicate.
- Frontend: new `Chat`, `Discover` and `My models` pages, a status bar component, Settings sections, and `src/lib/navigation.ts` / `src/App.svelte` routing; network threads reuse the existing `inference_stream`, `inference_cancel` and `consumer_command` operations.
- Permissions: `src-tauri/capabilities/default.json` gains only allow-permissions for the new custom native commands; no shell, filesystem, HTTP, dialog or opener plugin permissions.
- Scripts: `scripts/provision-model.py` and `scripts/provision-runtime.py` are unchanged and serve as the parity references; new parity tests compare native output with theirs.
- Storage: `<app data>/models/`, `runtimes/`, `chats/`, plus a staging area, per-load engine key files and a native settings file, where `<app data>` is Tauri's `app_local_data_dir` (non-roaming on Windows; see design decision 4).
- Tests: Rust parity, transfer, verification, runtime, fit and engine-lifecycle tests; frontend tests for plain-text rendering, history controls (including the on-by-default preference and its first-run disclosure), source-switch consent, browser preview and permissions; native platform smoke tests; book release gate 7.
- Documentation: `docs/chiral-book.md` is unchanged by this draft; its authority for this change is the text at `fe473508` plus the uncommitted 2026-11-16 *Author decisions* edit, items 1–11, and its follow-up recording the 2026-11-16 chat decisions (working-copy SHA-256 `eda22ce01020e0f2c6d8cc51c8081b7d9d9113b5c611441cb769f225af7d3933`; previously `8ee7fd8a114a8aefc7261a5716e2e80f10e051347f575cff645acf742e53e81c`). Its A.7 "not yet implemented" status and the milestone list are updated only after implementation and the release gate pass.
- Dependencies: no archive-order dependency on main specs or pending changes (new capabilities only). Later milestones build on this one: `specify-desktop-local-api-server` (M2) routes model names to models loaded under `desktop-local-runtime`; `specify-p2p-provider-transport` (M3) supplies the per-request Direct / Hole-punched / Relayed path label, with relay details, shown on network threads; `specify-desktop-share-online` (M4) owns sharing, the library's share status, refusal to delete or eject a model or remove a runtime backing an active share or qualification run, the engine hand-over to the provider daemon, and local chat on a shared model through admission, which M4 adds as its own requirement while M1 carries the carve-outs that point to it (an installation that backs an active share or an in-progress qualification run is not offered for loading or loaded by the desktop, and its local generation is dispatched or refused as M4 specifies); it also owns the refusals and acknowledgements for loading other models while a share is active or a qualification run is in progress, refusing logout while sharing or qualifying, sleep prevention, the tray sharing tooltip, Quit's list of active shares and the interception of application quit requests such as Cmd+Q while sharing or qualifying; `specify-provider-launch-reputation` (milestone 5) reuses the Hugging Face client rules, the bounded GGUF reader and the model ID form for its billing-honesty check, without an archive-order dependency.
- Out of scope: the local API server, libp2p transport, sharing and in-app qualification, an OS-confinement mechanism for the engine (a book release-gate item), the `<app data>/network/` and `local-server/` layout, importing externally provisioned model directories, relocating storage, non-GGUF or multimodal models, proxy support, installer packaging, and platform hardware qualification.
