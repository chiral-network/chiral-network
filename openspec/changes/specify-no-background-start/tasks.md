## 3. Acceptance evidence per requirement

Task 3.N corresponds to requirement N in the spec and to row N of the design coverage table. A task is checked only when existing passing tests prove every statement and scenario of its requirement. An unchecked task names the missing case. Each new test reads the repository or runs local processes only; none needs a chain, an engine or a network.

- [ ] 3.1 The application runs no chain node or miner. Existing evidence: `chain_rpc_api::tests::no_namespace_bypass` (owned by `chain-rpc-gateway`) and the `chain_client_tests` fixture, which panics on any method other than nine `eth_*` methods (`chain_client_tests.rs:299–389`). Missing:
  - a source test (Rust or Vitest) that the only non-test process construction in `src-tauri/src` is `engine_runtime.rs`'s `command()` (`Command::new`), and that it is called only by the llama-server launch and by `capture` for the fixed device-observer tools; that no source under `src-tauri/src`, `src` or `scripts` names a `geth`, `core-geth`, `conflux`, `ethminer` or other node or miner executable, and that no dependency manifest (`Cargo.toml`, `package.json`) adds a crate or package that bundles one;
