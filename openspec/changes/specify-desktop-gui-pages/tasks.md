## 3. Acceptance evidence per requirement

Task 3.N corresponds to requirement N in the spec and to row N of the design coverage table. A task is checked only when existing passing tests prove every requirement statement and scenario. An unchecked task names the missing cases.

- [ ] 3.1 Page actions invoke their documented native operations. Existing evidence: `fundingDisclosure.test.ts` › `presents an interrupted opening as journaled funding to resume, with the full disclosure`, `presents a failed top-up as unresolved funding to resume and never says that no money moved`, `discloses every A.1.6 item before a top-up, from the agreement's signed terms`; `requestRecovery.test.ts` › `a failure after a request ID offers Reconcile and sends nothing again`, `states that cancelling is not free and keeps Read status available`; `profileGate.test.ts` › `a loaded profile enables the same actions`. Missing: one rendered test per page with a recording stand-in boundary that takes every action in the mapping table and asserts the operation and arguments, including `discover` with `null` and with a model, `quote` with the exact `funding_wei`, the Playground stream request (`stream: true`, usage included, `max_tokens`), `inference_cancel`, `infer`, the five Usage selection reads, `receipt`, the credential operations, `credential_export` with and without a credential ID, `funding_recovery`, `cancel_funding`, `feedback`, the Wallet, Provider, Account, Network, Settings and Diagnostics operations; and a test that opening each page with a saved account and a journaled payment records only reads. Assert the listed arguments of each operation, not exact argument equality, since the credential actions also send arguments their operations ignore (design observation 8).
