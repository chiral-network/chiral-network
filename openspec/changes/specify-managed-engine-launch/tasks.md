- [x] 2.2 Detect a wildcard listener on the engine port (requirement 4, design code difference 2 and decision 5). In `ManagedEngine::start`, keep the endpoint bind and add a second probe: a `tokio::net::TcpSocket` of the endpoint's family with `set_reuseaddr(true)` that is bound, without `listen`, to that family's wildcard address (`0.0.0.0` or `[::]`) on the endpoint port. Hold both until just before the spawn, as now. Treat any failure of either as the occupied-port error. Do not merely turn `SO_REUSEADDR` off: on this host that also refused a port holding only a `TIME_WAIT` connection (decision 5). Regressions on macOS and Linux, which fail on macOS without the change: with the CPU fixture of `engine_runtime_tests.rs`, a `std::net::TcpListener` on `0.0.0.0:P` (and `[::]:P` with `IPV6_V6ONLY` where IPv6 loopback exists) makes `ManagedEngine::start` for `http://127.0.0.1:P` (respectively `http://[::1]:P`) fail with the occupied-port error before any spawn, and the listener still accepts a connection afterwards. A port whose only socket is a `TIME_WAIT` connection on `127.0.0.1:P`, made by accepting a connection, closing the accepted side first and then closing the listener, passes the port check. `start` then fails only at the spawn of the fixture's header-only executable, not with the occupied-port error. On Windows, record in task 4.1 whether both probes detect a wildcard listener. If they do not, add `SO_EXCLUSIVEADDRUSE` to the Windows probe in this task.
  Done 2026-11-18: `ManagedEngine::start` binds `wildcard_port_probe` (`engine_runtime.rs`): a `tokio::net::TcpSocket` of the endpoint's family, with `SO_REUSEADDR` on Unix and `IPV6_V6ONLY` for IPv6, bound without `listen` to `0.0.0.0:P` or `[::]:P`; then the existing endpoint listener. Both are held until just before the spawn, and a failure of either is the occupied-port error. The probe is bound first, because Linux refuses a wildcard bind on a port where a socket listens on a specific address, the launcher's own reservation included (`socket(7)`, `SO_REUSEADDR`), but not a specific-address bind beside a wildcard socket that does not listen; this order also passes on macOS. No Linux host was used: the Linux behavior is from the kernel's documented rule, and the `TIME_WAIT` and daemon regressions would fail on Linux if the order were wrong. On Windows the probe does not set `SO_REUSEADDR`, because there the option lets a bind share a port that another socket holds (mio leaves it unset there too); whether both probes detect a wildcard listener on Windows is still recorded by task 4.1, and `SO_EXCLUSIVEADDRUSE` was not added. Regressions: `engine_runtime::tests::a_listener_on_the_engine_address_or_its_wildcard_is_refused_before_spawn` (a listener on `127.0.0.1:P` and on `0.0.0.0:P`, and, where IPv6 loopback exists, on `[::1]:P` and an `IPV6_V6ONLY` `[::]:P`, each makes `start` fail with the occupied-port error, which precedes the spawn, and still accepts a connection afterwards; the same-address case is also task 3.4's) and `engine_runtime::tests::a_port_holding_only_time_wait_connections_passes_the_port_check` (the `TIME_WAIT` connection is made as above; on macOS the test first asserts that a bind without `SO_REUSEADDR` is refused, so the connection exists; `start` then fails with "cannot start pinned native llama-server" on this host). Without the probe the first test fails on macOS at `0.0.0.0` (and at `[::]` when only the IPv6 probe is removed). With the probe's `SO_REUSEADDR` removed, or with the endpoint bound without `SO_REUSEADDR` and no probe, the second test fails.
