## 2. Close code differences

- [x] 2.1 Record client disconnects as client interruptions (requirements 11 and 12, design code difference 1). In `src-tauri/src/inference_gateway.rs`, a client that closes its connection must reach `Settlement::finish("disconnected")`, not `Drop`'s `"interrupted"`. This applies to a non-streaming client during generation, and to any client during `engine.dispatch`. One way: move dispatch, and the non-streaming `stream_inner` collection, into a spawned task that owns the `Settlement`. That task answers the handler through a oneshot channel and treats a closed receiver as `client_disconnected`, as the streaming worker already does through `sender.closed()`. Then in `src-tauri/src/performance.rs` `outcome`, `interrupted` may remain only for interruptions the gateway cannot attribute, such as a task panic or a runtime shutdown. Classify those as `provider_incomplete`, so the eligibility list loses `interrupted_unknown_origin`, and update `exclusions_do_not_erase_a_previously_observed_miss` accordingly. Settlement must still happen exactly once, and the request must still settle when the handler is dropped. Regressions, which fail without the change, are gateway tests with a fixture engine that delays its first token:
  - a non-streaming in-envelope request whose client drops the connection 500,000 µs after the body arrived must settle with eligibility `client_interrupted`, `attained` null and remedy `none`, and must add no `performance_observations` row;
  - three such requests in a row must not latch withdrawal;
  - when the fixture first token arrives at 2,100,000 µs and the client then disconnects, the request must settle as a measured miss with `inference_waiver` and one miss observation.

  Done 2026-11-17: a spawned `execute` task now owns the `Settlement` from `engine.dispatch` to settlement, for both response modes and embeddings. It answers the handler through a oneshot, and a closed reply or SSE body settles `disconnected`. The settlement is released before the answer, and leaving the task drops the engine request, which cancels it upstream. `outcome` has no `interrupted_unknown_origin`, so `interrupted` (panic, shutdown, failed durable write) is `provider_incomplete`. `exclusions_do_not_erase_a_previously_observed_miss` now asserts that, plus a disconnect at 500,000 µs (`client_interrupted`) and one after a 2,100,000 µs TTFT (measured miss). The regressions are gateway tests on real TCP sockets that are closed mid-request: `non_streaming_disconnects_before_a_miss_are_client_interruptions_and_never_latch` covers the first two bullets, `a_measured_miss_survives_a_later_non_streaming_disconnect` covers the third, and `disconnect_before_the_engine_responds_is_a_client_interruption_in_both_modes` covers dispatch in both modes. Each also checks that the engine request was dropped. Without the change, every test fails: the status becomes `interrupted_unknown_usage`, eligibility becomes `interrupted_unknown_origin`, and the third disconnect latches withdrawal.
- [ ] 2.2 Treat a 0 µs TTFT as no evidence of attainment (requirements 4 and 9, design code difference 2). In `src-tauri/src/performance.rs`, the `passes` predicate in `validate_evidence` must require `r.ttft_us > 0`. In `outcome`, treat `ttft_us == Some(0)` like a missing TTFT: not attained, and provider-incomplete unless a miss was measured or the client interrupted. In `scripts/qualify-provider.py`, `passes` must require `0 < sample["ttft_us"]`. Regressions, which fail without the change:
  - an evidence fixture in which two samples of one 25-sample bucket have `ttft_us` 0 fails validation;
  - `outcome` with `Some(0)` TTFT, a valid decode interval and status `completed` is not attained;
  - a runner `passes` case with `ttft_us` 0 returns false.
- [ ] 2.3 Reject qualification samples outside every prompt boundary (requirement 8, design code difference 3). In `src-tauri/src/performance.rs` `validate_evidence`, reject evidence that contains any sample whose `prompt_tokens` is outside 120–128, 504–512, 1,016–1,024 and 2,040–2,048. Keep the per-bucket minimum of 20 and the 100-sample minimum per endpoint/mode.
