## Goals / Non-Goals

Goals:
- Cover the complete typed offer/model/profile/quote vocabulary without duplicating the foundation's signing/money algorithms.
- Distinguish receiver syntax/consistency checks, native issuer policy, native deployment qualification and consumer agreement checks.
- Preserve immutable accepted terms and the narrow evidence-only renewal exception.
- Expose the native embedding output-price gap as work to prove and fix, not silently declare it implemented.

Non-goals:
- Deploy a provider, qualify real hardware, collect funding, change an account or alter the whitepaper.
- Specify DHT pagination/revision reconciliation, DNS pinning transport implementation, full funding/nonce/chain state machines or runtime measurement/waiver accounting in this change.
- Tighten arbitrary remote quote lifetime/nonce syntax simply because the local issuer emits a narrower form; remove existing recovery paths; or reinterpret legacy state.

## Decisions

1. **Layered acceptance, not a universal metadata validator.** `ModelSpec` describes broad signed capabilities; native GGUF tasks, qualified generation profiles and public production admission have stricter rules. For example, base declaration validation alone is not proof that a runtime can jointly execute its advertised APIs. Preserve that boundary rather than turning receiver syntax into a false qualification claim.
2. **Reuse strict wire primitives.** All fields use `inference-wire-foundation` representations. Nullable model options retain the typed codec's canonical null representation; no alternate signing serializer or public schema aliases are introduced.
3. **Preserve issuer/receiver distinctions.** Local offers normally last 120 seconds while receivers accept at most 3,600; local quotes last 300 seconds while current native acceptance checks future skew, ordered timestamps and context-dependent freshness. Native issuance generates random quote IDs/nonces; verification binds the supplied signed nonce rather than proving its randomness. No additional receiver lifetime/nonce rule is invented here.
4. **Record currently implemented profile limits.** The whitepaper names exact fields and delegates detailed consistency to the implementation reference. Preserve existing text/digest limits, platform/backend pairing, memory accounting, device uniqueness, split/cache/batch rules and workload bounds. Declaration validity still is not measured evidence.
5. **Enforce input-only embedding terms at the native boundary.** The whitepaper explicitly requires zero output limit/rate. A provisioning-only check does not protect a directly supplied provider configuration. Add a focused regression and enforce the same rule before native publication/admission; do not merely hide a nonzero rate in the UI or normalize it to zero.
6. **Keep non-reserving quote formation separate from admission and settlement authority.** Public proposal is intentionally unauthenticated; its exact signed terms are overbookable, not owner authorization, a paid-intent lease, free-account capacity, execution capacity or credit. Ordinary offer/readiness gates still apply, but full opening capacity alone cannot refuse otherwise eligible quoting. Paid capacity is decided atomically at payer-authenticated funding-intent before durable acknowledgement/client broadcast; free capacity is decided at authenticated first opening without fake payment. New-funding readiness can be closed while accepted balances/recovery remain available.
7. **Bound provider resources, never the unauthenticated named wallet.** Retain at most 10,000 standalone quotes per ledger, independently of at most 10,000 active original paid-intent leases. Keep 64 non-queuing control readers, 96 KiB bodies and five-second read deadlines. Claim a durable provider-ledger 600/minute work permit after validation and before signing; it remains spent after signing/insertion/delivery failure. Separately charge 600/minute committed insertions atomically with quote storage; failed insertion rolls back this charge, and successful issuance is not refunded by response loss, expiry, acknowledgement or opening. Each budget has its own durable non-regressing effective-minute clock; work initializes its first minute exhausted, while committed issuance preserves retained global evidence under the aligned rate contract. Neither clock changes signed timestamps. Remove both old named-wallet gates together; optional source controls use transport/trusted-proxy identity, not the named wallet or untrusted forwarding headers. Challenge and per-inference rules remain unchanged.
8. **Preserve accepted originals through capacity pressure and ambiguity.** Full paid admission refuses without acknowledgement, accepted intent, account, credit or submission; an honest provider must not broadcast the refused original. A client persists a valid acknowledgement before submitting the exact prepared bytes. Signed bytes still permit dishonest provider broadcast; lost replies are ambiguous and require recovery of the same intent/acknowledgement/transaction, not automatic replacement. Once acknowledged, expiry, restart or later capacity pressure cannot revoke terms or sender/nonce ownership. Healthy safe-frontier evidence remains necessary for credit. Cached accepted-original, existing-account, top-up and settlement recovery acquire no fresh quote/work/rate/opening-capacity gate. Existing authenticated free-opening account bounds remain separate.

## Advertised-origin implementation

Task 2.1.4 corrects static acceptance of `localhost.` and names below `*.localhost.` in the shared `offer_registry::validate_endpoint` boundary. Only reserved-name classification strips terminal DNS root dots, after URL parsing/normalization. The development exception still uses literal loopback or exact `localhost`; absolute aliases cannot obtain that exception. Returned URLs and signed endpoint strings are not rewritten.

The origin regression covers plain, case-folded, percent-encoded and IDNA dot spellings, nested localhost subdomains and repeated terminal dots, with HTTPS/443 and development-style HTTP(S) ports in both modes. Each case first establishes that URL parsing accepts the spelling. Positive controls retain public absolute DNS names, including `localhost.example.org.`, and existing exact-localhost/literal-loopback behavior. These are deterministic static admission checks, not DNS, reachability or transport-bypass evidence.

The shared validator remains the gate for offer-registry insertion, provider public-endpoint configuration and safe outbound client construction. DNS address validation/pinning, disabled redirects/proxies and private-engine configuration are unchanged. Embedding template enforcement and the other incomplete commercial tasks remain open; this correction does not complete the change or authorize archival.

## Native embedding-price implementation

Task 2.2 enforces zero output price inside `ProviderConfig::validate`, which is used by both configuration loading and provider startup before secret access or service construction. The check reuses the existing canonical integer parser and examines every model with the `embeddings` capability, independent of capability position, development mode or managed-runtime selection. It does not impose zero output prices on generation or reinterpret broad remote offer declarations.

Two regressions in `inference_commercial_terms_test.rs` exercise both direct validation and actual configuration-file loading. They pair free/paid input and zero-output controls with one-wei/maximal nonzero rates and noncanonical zero spellings, preserve priced development generation, and reject an invalid embedding price in either model position. Synthetic paths and CPU settings test configuration admission only: no keys, artifact inventories, engines, RPC or qualification are supplied.

Invalid configurations must be corrected explicitly; no rate is normalized, no existing quote/account/balance is rewritten, and no ledger migration is introduced. The distinct managed-inventory template requirement remains task 2.3.
