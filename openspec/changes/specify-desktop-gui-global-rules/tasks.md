## 3. Acceptance evidence per requirement

Task 3.N corresponds to requirement N in the spec and to row N of the design coverage table. A task is checked only when existing passing tests prove every requirement statement and scenario. An unchecked task names the missing cases.

Missing: a test that the capability file grants only the four native commands plus the event and window permissions, and no HTTP or other plugin permission; a test that the production CSP keeps `connect-src` to the IPC channel; a test that the page references no remote origin (task 2.8); a native check that the webview makes no request outside the command channel at startup and during discovery, funding, top-up, credential issue and streaming; a rendered test that a two-line native error appears verbatim in an error callout, including a failed journal read on the Marketplace (task 2.12); a test that a failed logout reports the native error in an error notification.

Existing evidence: `stores.test.ts` › `drops legacy runtime and secret fields instead of restoring them`; `native.test.ts` › `rejects paid/native operations without a desktop runtime`; `consumer::tests::explicit_credential_issue_recovers_default_without_rotating_on_resume`, `resumed_open_accounts_preserve_exported_credentials_and_refresh_funding_status`, `persisted_credentials_are_private_and_symlinks_rejected`.
