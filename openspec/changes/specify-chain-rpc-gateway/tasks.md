## 3. Acceptance evidence per requirement

Task 3.N corresponds to requirement N in the spec and to row N of the design coverage table. A task is checked only when existing passing tests prove every statement and scenario of its requirement. An unchecked task names the missing case.

- [ ] 3.1 The gateway requires its own protected inbound bearer on every bind address. Existing evidence: the two startup tests of task 2.1, and the exactly-32-character start in `the_gateway_serves_rpc_only_with_its_bearer_and_never_to_a_browser_origin`. Missing: a run on native Windows in which a bearer file readable by another account is refused.
- [x] 3.2 Every RPC request is authenticated before it is read or forwarded.
  Done 2026-11-18: `the_gateway_serves_rpc_only_with_its_bearer_and_never_to_a_browser_origin` covers every scenario: no bearer and `X-Forwarded-For: 127.0.0.1` alone; a different bearer of equal length, a 16-character prefix, the bearer plus one character, the bearer without its scheme and the upstream bearer (each 401, JSON-RPC error with null `id`, `no-store`, nothing forwarded); 200 refusals followed by an admitted request; a valid request answered with `no-store`; and every upstream request carrying only the upstream bearer. The constant-time comparison is established by code inspection (`subtle::ConstantTimeEq`), not by a test. Behaviour through a real Caddy ingress is deployment evidence (task 4.1).
- [x] 3.3 Browser-origin requests are refused.
  Done 2026-11-18: the same test sends the valid bearer with `Origin: https://example.org` and with `Origin: null`; both are 401 and not forwarded. With the `Origin` check removed from `auth` it fails (200 instead of 401), and the file was restored byte-identical.
- [ ] 3.4 Only an exact eth_* allowlist is forwarded, with fixed parameter shapes. Existing evidence: `no_namespace_bypass`, `allowlist_is_exactly_ten_eth_methods`, `validates_supported_shapes_only`, `native_estimation_is_independently_bounded` and the process-level `net_version` refusal. Missing: refusals of a malformed `eth_getTransactionReceipt` hash, an odd-length or 16 KiB + 1 byte `eth_sendRawTransaction`, an `id` of 129 bytes and an extra envelope member; a process or router test in which a batch of a valid `eth_blockNumber` and a `net_version` answers 400 and the upstream receives nothing; a router test in which an `eth_sendRawTransaction` signed for chain 1 is answered as rejected and never reaches `eth_sendRawTransaction` upstream; and a test that an upstream error message is not echoed.
- [ ] 3.5 Transport and admission are bounded. Existing evidence: `block_transport_and_gateway_enforce_separate_request_response_and_batch_caps`, `large_hash_only_blocks_verify_canonical_funding_through_gateway` and `submission_budget_is_independent`. Missing: router tests refusing an empty batch and a nine-member batch with 400 before forwarding; a mixed read-and-submission batch refused with 429 when the submission budget is exhausted, with no upstream request; and a concurrency refusal that answers 429 at once instead of queuing.
- [ ] 3.6 The gateway verifies network identity and keeps its own persistent journal. Existing evidence: `public_identity_is_pinned_and_genesis_is_not_refetched_per_operation` (library) and the gateway's start against a matching upstream. Missing: process tests in which an upstream answering chain ID 1030, or another genesis hash, makes the gateway exit nonzero before listening; and a restart test showing the same `wallet-journal/transactions.sqlite3` reused with mode `0700` on its directory and `0600` on the file.
- [ ] 3.7 Liveness and readiness are unauthenticated local probes. Existing evidence: `/healthz` and `/readyz` answer 200 without a bearer in `the_gateway_serves_rpc_only_with_its_bearer_and_never_to_a_browser_origin`. Missing: a process test in which the upstream stops answering and `/readyz` turns 503 with `{"ready":false}` while `/healthz` stays 200; and a provisioning test reading the generated public Caddyfile's RPC domain block (only `/api/chain/rpc` to `127.0.0.1:8547`, everything else 404).
- [ ] 3.8 Provisioning and preflight keep the gateway authenticated. Existing evidence: the three tests of `scripts/test_provider_preflight.py` and the three of `scripts/test_provision_provider.py` (identical bearers, distinct or absent upstream bearer, and a calibration input without `rpc_token_file` or with a 31-character token, each refused before the destination exists). Missing: a provisioning test that the generated `provider.json` and `relay.json` name `secrets/rpc.token` as their RPC bearer while `rpc-gateway.json` names only `secrets/upstream-rpc.token`.
